# 기록 (REC)

내 사진을 월 단위 달력으로 모아 보는 기록 탭이다. 달력은 일요일에 시작하고, 사진이 있는 날짜 칸에는 썸네일을 보여 준다. 월 선택지는 서버의 기록 연월 목록(`GET /posts/calendar/months`)에 KST 기준 현재 달을 합친 것이며(D-19), 월 이동은 이 선택지 안에서만 한다. 날짜는 사진이 있는 칸만 선택할 수 있고, 선택하면 아래에 그날의 사진과 동작("피드에서 보기", "전시 보러가기")이 나온다. 달력은 `PENDING`과 `APPROVED` 사진만 보여 주며(POST-009) 검수 대기(`PENDING`)는 "사진 반영 중" 배지로 알린다. 한 번 불러온 달은 캐시해 먼저 보여 주고 뒤에서 다시 확인한다. 삭제한 게시물은 캐시와 새 응답 모두에서 걸러 낸다. 달력은 이미지로 저장할 수 있다. 게스트는 기록 탭에서 API를 호출하지 않고 로그인 안내 토스트만 본다(D-05).

- 관련 규칙: [POST-009](../../reference/business-rules/rules/post.md#post-009-캘린더), [POST-007](../../reference/business-rules/rules/post.md#post-007-공개-범위)
- 관련 결정: [D-04](../decisions.md#d-04-좋아요는-모든-화면에서-낙관적-갱신--실패-시-롤백토스트), [D-05](../decisions.md#d-05-게스트-제한), [D-19](../decisions.md#d-19-기록-탭의-현재-달), [D-20](../decisions.md#d-20-오류-화면과-토스트), [D-23](../decisions.md#d-23-게시물-상세의-수정삭제-버튼)
- 근거 약어: iOS = [legacy-ios](../../reference/legacy-ios.md), AN = [legacy-android](../../reference/legacy-android.md), API = [api-contract](../../reference/api-contract.md). 서로 다른 동작은 "고른 기준"에 이유를 적었다.

## 화면

### 1. 기록 화면

- 진입 조건: 로그인 회원이 하단 탭에서 기록을 눌렀을 때. 게스트는 화면에 들어가지 않는다(REQ-REC-040).
- 구성 요소: 월 헤더(이전 달 화살표, 연월 라벨, 다음 달 화살표), 요일 머리글(일월화수목금토), 달력 격자(날짜 칸, 사진이 있는 칸은 썸네일), 선택한 날짜의 사진 영역(썸네일, "사진 반영 중" 배지와 안내, 동작 버튼), "이미지로 저장" 버튼.
- 사용자 동작: 화살표로 달 이동, 연월 라벨을 눌러 월 선택, 날짜 칸 선택, "피드에서 보기", "전시 보러가기", "이미지로 저장", 오류 화면의 "다시 시도"·"로그인 하기".

### 2. 월 선택 (휠 또는 목록)

- 진입 조건: 연월 라벨을 눌렀을 때.
- 구성 요소: 선택 가능한 연월 목록(최신순), 확인과 닫기.
- 사용자 동작: 연월을 고르면 그 달로 이동한다. 현재 선택과 같거나 선택지에 없는 달은 아무 일도 없다.

### 3. 날짜 선택 시트 (제목 "날짜 선택")

- 진입 조건: 달력의 날짜 선택 진입점을 눌렀을 때. 제목은 "날짜 선택"이다.
- 구성 요소: 같은 달의 사진이 있는 날짜 목록.
- 사용자 동작: 날짜를 고르면 그 날짜가 선택된다. [추정] 위 월 선택과 날짜 선택이 한 시트의 두 단계인지 별도 시트인지는 소스에서 갈라 확인하지 못했다(확인 필요).

### 4. 오류 화면

- 진입 조건: 처음 불러오기 실패(REQ-REC-024).
- 구성 요소: 오류 제목과 버튼(401은 "로그인 하기", 그 밖은 "다시 시도").

| Error | 캐시 없는 달의 첫 불러오기 실패 | 오류 화면(401/400/기타) | "다시 시도" → Loading, "로그인 하기" → 로그인 화면 |
| GuestBlocked | 게스트가 기록 탭을 누름 | 토스트만, 화면 진입 없음 | – |

## API 호출

공통: 인증 헤더 필요. 읽기 `GET`은 D-21의 네트워크 오류·5xx 자동 재시도(0.5초, 1초, 최대 2회)를 따른다.

| 순서 | 호출 | 시점 | 핵심 |
| --- | --- | --- | --- |
| 1 | `GET /posts/calendar/months` | 화면 진입, 포그라운드 복귀 | 응답 `{months:[{year,month}]}` 최신순, 없으면 `[]`. 기록 없는 현재 달은 서버가 넣지 않으므로 클라이언트가 합친다(REQ-REC-002). |
| 2 | `GET /posts/calendar?year=&month=` | 달 이동, 진입, 재검증 | 응답 `{year, month, posts[{topicDate, postId, thumbnailImageUrl, status}]}`. 검증은 REQ-REC-018. |

### 실패별 처리

| 호출 | 실패 | 처리 |
| --- | --- | --- |
| calendar | 401(갱신 불가) | 캐시 없음: 오류 화면 "로그인이 필요해요" + "로그인 하기" |
| calendar | 400 | 캐시 없음: "조회할 수 없는 연월이에요" |
| calendar | 403(정지) | D-08 문구 |
| calendar | 네트워크·5xx·계약 위반 | 캐시 없음: 오류 화면 "기록을 불러오지 못했어요" + "다시 시도"; 캐시 있음: 토스트 |
| months | 모든 실패 | 현재 달만으로 진행하고 토스트는 보이지 않는다 [추정] |

## 플랫폼별 허용 차이

- 월 선택 UI: 모바일은 휠 또는 하단 시트, 웹은 드롭다운이나 모달을 써도 된다. 선택지 집합과 동작은 같아야 한다.
- 이미지 저장 방식: 모바일은 사진 보관함, 웹은 파일 다운로드. 파일 이름과 PNG 형식은 같아야 한다.
- 배지 안내 풍선은 모바일은 터치로 열고 웹은 클릭 또는 호버로 열어도 된다.
- 달력 이미지의 정확한 픽셀 크기와 디자인은 플랫폼 구현 소관이다(확인 필요의 내용 항목은 같아야 한다).

## 확인 필요

- 규칙 POST-009는 기록 연월 목록이 "빈 달의 선택이나 월별 조회를 제한하지 않는다"고 하지만, Android는 월 이동을 `availableMonths`(서버 목록 + 현재 달) 안으로 제한한다. 이 명세는 Android와 D-19를 따랐다. 목록에 없는 과거 달을 직접 볼 수 있어야 하는지는 결정이 없다.
- 서버가 알 수 없는 `status`(PENDING/APPROVED 외)를 보내면 항목만 건너뛸지 전체 응답을 계약 위반으로 볼지 정한 규칙이 없다. 이 명세는 전체를 계약 위반으로 본다(REQ-REC-018).
- 월 목록 조회가 실패했을 때의 표시(토스트 여부)는 소스에서 확인하지 못했다. 현재 달만으로 진행하고 조용히 넘기는 것은 [추정]이다.
- 날짜 선택 시트와 월 선택이 같은 시트인지 별도 시트인지, 날짜 칸을 직접 눌러 선택하는 것과 시트 선택의 관계가 소스에서 갈라지지 않았다.
- 달력 이미지에 담기는 내용(썸네일 포함 여부, 연월 제목, 로고)과 사진이 하나도 없는 달에서 "이미지로 저장"을 허용할지는 문서에 없다.
- 날짜 칸의 모양(선택 표시, 오늘 표시, 미래 날짜 흐림)은 문서에 정확히 없어 플랫폼 디자인에 맡긴다.
- 삭제 직후 `availableMonths`에서 사진이 없어진 달을 어떻게 다룰지(REQ-REC-029)와 삭제 후 선택 날짜 이동(REQ-REC-028)은 [추정]이다.
- 정지 회원의 기록 조회 가능 여부는 API 문서에서 확인하지 못했다(REQ-REC-042는 D-08에 의존).
