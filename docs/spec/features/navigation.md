# 내비게이션 (NAV)

메인 화면은 하단 탭 4개(홈, 전시, 기록, 설정)와 가운데 업로드 버튼으로 이루어진다. 업로드 버튼은 탭이 아니라 진입 게이트를 거쳐 업로드 화면을 연다. 이 문서는 탭 전환과 상태 복원, 게스트가 막히는 지점, 화면 간 이동과 백스택, 하단 바가 숨는 화면, 삭제·업로드 뒤 복귀, 푸시 탭 보류 규칙을 정한다. 화면 내부 동작(홈 히어로, 전시 목록 등)은 각 기능 문서가, 푸시 탭 목적지 표는 [notification-push.md](notification-push.md)가 소유한다.

- 관련 규칙: 없음(서비스 정책이 아닌 클라이언트 구조 규칙)
- 관련 결정: [D-05](../decisions.md#d-05-게스트-제한), [D-11](../decisions.md#d-11-푸시-탭-처리), [D-14](../decisions.md#d-14-업로드-진입업로드-흐름), [D-19](../decisions.md#d-19-기록-탭의-현재-달), [D-20](../decisions.md#d-20-오류-화면과-토스트), [D-22](../decisions.md#d-22-분석-이벤트), [D-23](../decisions.md#d-23-게시물-상세의-수정삭제-버튼)
- 근거 약어: iOS = [legacy-ios](../../reference/legacy-ios.md), AN = [legacy-android](../../reference/legacy-android.md), API = [api-contract](../../reference/api-contract.md).
- 앱 시작 흐름과 로그인 전환은 [boot-auth.md](boot-auth.md), 분석 이벤트 상세는 [common-infra.md](common-infra.md).

## 화면

### 메인 하단 바

- 진입 조건: 인증 사용자 또는 게스트가 메인에 있을 때.
- 구성 요소(왼쪽부터): 홈 `tab-home`, 전시 `tab-display`, 가운데 업로드 버튼 `tab-upload`(아이콘 "+", 접근성 이름 "추가"), 기록 `tab-record`, 설정 `tab-settings`.
- 사용자 동작: 탭 선택(선택 표시 하나), 업로드 버튼 누르기(게이트 시작).

### 화면 지도

탭 루트 4개와, 그 위에 쌓이는 화면들이다. `[문서]`는 화면 내부를 정의하는 문서다.

| 구분 | 화면 | 분석 이름 | 여는 곳 | 문서 |
| --- | --- | --- | --- | --- |

| 탭 루트 | 전시 | `display` | 하단 바, 홈 랭킹 링크, 업로드 성공 확인, 기록 "전시 보러가기" | display-feed.md |

| 임의 탭 | 업로드 버튼 | 선택 표시 변화 없음, 게스트면 토스트, 아니면 게이트 |

## API 호출

내비게이션 자체는 API를 부르지 않는다. 이동 동작이 시작하는 호출은 다음 문서가 정한다.

| 동작 | 호출 | 정의 문서 |
| --- | --- | --- |
| 인증 사용자의 업로드 버튼 | `GET /posts/today`, 이어서 `GET /topics?date=` | upload-edit.md (D-14) |
| 기록 탭 진입 | `GET /posts/calendar`, `GET /posts/calendar/months` | record.md |
| 알림 항목·푸시 탭 | `PATCH /notifications/{id}/read` 후 이동 | notification-push.md (D-11) |
| 게시물 삭제 | `DELETE /posts/{id}` | display-feed.md |

게스트 제한 동작(REQ-NAV-013~019)은 위 어떤 호출도 하지 않는다.

## 플랫폼별 허용 차이

- 뒤로 가기: iOS 가장자리 스와이프와 내비게이션 바 뒤로 버튼, Android 시스템 뒤로 제스처·버튼, Web 브라우저 뒤로·앞으로. 도착 화면과 상태 유지 규칙은 같아야 한다.
- iOS의 하단 바 compact 동작(스크롤 방향 임계값 16에서 축소)이나 Liquid Glass 변형, Android의 하단 바 머티리얼 스타일은 시각 효과라 자유다.
- 화면 전환 애니메이션, 시트로 열지 전체 화면으로 열지는 자유다(예: 약관 문서는 iOS 시트, Android 다이얼로그).
- 토스트와 스낵바 구분은 자유다. 표시 시간 2.5초와 화면 기준 위치는 같아야 한다.
- Web은 각 화면에 URL을 줄 수 있고, 새로고침 때 탭 상태를 URL에서 복원할 수 있다. 단 게스트 제한과 백스택 규칙은 같아야 한다.
- Web에는 하드웨어 뒤로 가기와 앱 종료 개념이 없으므로 REQ-NAV-026의 "앱 종료"는 해당하지 않는다.

## 범위 밖

- 외부 딥링크와 유니버설 링크(기존 두 앱 모두 없음).
- 푸시 탭 목적지 표와 읽음 처리(notification-push.md).
- 각 탭 내부 화면의 요구사항(home.md, display-feed.md, record.md, upload-edit.md).

## 확인 필요

1. iOS 기존 앱의 탭 상태 복원 규칙(전시·기록·설정이 상태를 유지하는지, 홈이 항상 새로 시작하는지)은 분석 문서에 없다. REQ-NAV-004~005는 Android 규칙을 모든 플랫폼에 적용한 [추정]이다.
2. 하단 바가 숨겨지는 화면은 기존 문서에서 피드만 확인된다. 알림함·알림 상세·배너 웹·업로드·피드백·사인 변경에서의 표시 여부는 [추정](모두 숨김)이다.
3. 비홈 탭 루트에서의 뒤로 가기(홈으로 가는지, 바로 앱을 벗어나는지)와 탭 재선택 동작(홈 재선택 시 맨 위 스크롤 등)은 기존 문서에 전시 재선택 외 기록이 없다.
4. 업로드 성공 화면에서 시스템 뒤로 가기를 눌렀을 때 정확한 목적지(업로드를 시작한 탭인지 홈인지)는 기존 문서에 없다. 임시 동작: 업로드를 시작하기 전 화면으로 간다.
