# 에이전트 시나리오: ONB, SIGN

[catalog/onboarding-signature.md](../catalog/onboarding-signature.md)에서 구분이 `A`인 TC를 서브에이전트가 시뮬레이터·에뮬레이터·브라우저와 개발 서버에서 직접 확인하는 절차다. 공통 전제(개발 서버 주소, 테스트 계정은 "실행 시 사용자에게 받은 계정", 비밀값 비기록, 사용자 Mac에서 실행, 결과를 parity-matrix에 반영)는 [boot-auth.md의 공통 전제](boot-auth.md#공통-전제-이-문서의-모든-시나리오)와 같다.

## ONB

### AG-ONB-001 실제 카카오 신규 가입 end-to-end

- 대응 TC: TC-ONB-050, TC-ONB-051
- 사전 조건: 앱 신규 설치(세션 없음). 카카오 계정은 **실행 시 사용자에게 받은 계정**으로, 개발 서버에 **아직 가입되어 있지 않은** 계정이어야 한다(이미 가입된 계정이면 SIGN_UP_REQUIRED가 오지 않는다. 필요하면 먼저 AG-AUTH-004로 탈퇴해 사용자 확인 하에 미가입 상태로 만든다). 시뮬레이터에서 손가락(마우스) 입력이 가능해야 한다. 개발 서버 정상.
- 단계:
  1. 로그인 화면에서 "카카오로 계속하기"를 탭하고 카카오 로그인을 마친다.
  2. 약관 화면이 열리는지 확인한다. 아무것도 선택하지 않은 상태에서 "다음"이 비활성인지 본다.
  3. "전체 동의"를 눌러 두 필수 항목이 선택되고 "다음"이 활성되는지 확인한 뒤 "다음"을 누른다.
  4. 사인 화면에서 마우스/터치로 이름 모양의 획을 그린다. "되돌리기", "전체 지우기"를 한 번씩 써 보고 다시 그린다.
  5. "이 사인으로 할래요"를 탭해 미리보기("이렇게 보여요")를 확인한다.
  6. "시작하기"를 탭하고 사인 처리 대기 동안의 화면(스피너 유지)을 캡처한다. 가입이 완료될 때까지 최대 60초 기다린다.
  7. 홈이 열리는지, 알림 권한 안내가 첫 홈 진입 기준으로 한 번 뜨는지 확인한다(권한 다이얼로그 자체는 AG-PUSH-001에서 본다).
  8. 설정 탭의 사인 카드에 방금 그린 사인이 보이는지 확인한다(처리 지연이 있으면 몇 초 뒤 설정 탭을 다시 열어 확인).
  9. 앱을 강제 종료 후 재시작해 홈이 유지되는지 확인한다.
- 기대 결과: 약관 → 사인 → 미리보기 → 가입 완료 → 홈. 사인 처리 중 스피너가 유지되다가 성공한다(PENDING 재시도는 최대 약 10초 안에 끝나지 않으면 "사인 처리에 시간이 걸리고 있어요. 다시 시도해 주세요."가 나올 수 있으며, 그 경우 다시 시도해서 성공하는지까지 기록한다). 홈은 회원 모드이고 설정에서 사인 썸네일이 보인다. 푸시 기기 등록이 시도된다.
- 확인 방법: 단계별 스크린샷, 디버그 로그에서 요청 순서(POST /auth/social-signup/signature/uploads → 사인 PUT → POST /auth/social-signup)와 SIGNATURE_PROCESSING_PENDING 횟수, 응답 상태. 사인 썸네일은 사용자에게 받은 토큰으로 `GET /users/me/signature`를 읽기 전용으로 조회해 URL이 비어 있지 않은지 확인할 수 있다(토큰은 기록하지 않음).
- 되돌릴 수 없음: 예(개발 서버에 새 회원이 생성됨. 정리는 AG-AUTH-004 탈퇴로 하며 사용자 확인이 필요하다).
- 플랫폼 차이: iOS 시뮬레이터와 Android 에뮬레이터는 같은 계정으로 연속 가입할 수 없다(첫 플랫폼에서 가입하면 다음 플랫폼에서는 기존 회원 로그인). 사용자와 합의한 대표 플랫폼 1곳에서 신규 가입을 수행하고, 나머지 플랫폼은 가입 완료 이후 상태를 AG-AUTH-001 경로로 확인하거나 탈퇴 후 재가입으로 각각 수행한다. Web은 Q-02 결과에 따른다.

### AG-ONB-002 실제 Notion 약관 문서 열기

- 대응 TC: TC-ONB-052
- 사전 조건: 약관 화면까지 진입 가능한 상태(AG-ONB-001 2단계) 또는 설정 탭의 약관 행. 시뮬레이터가 인터넷에 연결됨. 계정 상태는 무관하나 로그인이 필요하면 가입된 회원 계정을 쓴다.
- 단계:
  1. 약관 화면에서 "(필수) 서비스 이용약관"의 "보기"를 탭한다. 문서가 열리는 데 걸린 시간을 기록한다.
  2. 문서 본문을 위아래로 스크롤하고, 문서 안의 링크 하나를 탭한다(앱 안 이동인지 외부 브라우저인지 본다).
  3. 시트·다이얼로그(Web은 새 탭)를 닫고 약관 화면 체크 상태가 유지되는지 확인한다.
  4. "(필수) 개인정보 처리방침"의 "보기"도 1~3을 반복한다.
  5. 네트워크를 끊고 "보기"를 눌러 오류 화면("문서를 불러오지 못했어요", "다시 시도")이 뜨는지, 네트워크 복구 후 "다시 시도"가 문서를 여는지 확인한다.
- 기대 결과: 두 문서가 각각 읽을 수 있게 로드된다. 허용 호스트(notion.com/.so/.site, https) 문서만 앱 안에서 열리고 다른 호스트 링크는 외부 브라우저로 간다. 닫아도 체크 상태 유지. 오프라인에서는 오류와 다시 시도.
- 확인 방법: 스크린샷, 디버그 로그에서 열린 URL의 호스트와 scheme(경로 일부만 기록), screen_view `terms_of_service`, `privacy_policy` 전송.
- 되돌릴 수 없음: 아니오.
- 플랫폼 차이: iOS는 WKWebView 시트, Android는 WebView 다이얼로그, Flutter·RN은 각 웹뷰 패키지, Web은 새 탭이다. Notion 페이지의 쿠키 배너나 로딩 방식 차이는 기록만 한다.

## SIGN

### AG-SIGN-001 사인 그리기 손 제스처 품질

- 대응 TC: TC-SIGN-044
- 사전 조건: 각 플랫폼의 사인 화면에 진입 가능한 상태(가입된 회원이라면 설정 → 사인 변경, 아니면 AG-ONB-001의 4단계). 서버 호출은 필요하지 않다(미리보기 직전까지만 확인). 기기 상태는 시뮬레이터/에뮬레이터/브라우저 기본 해상도. iOS는 시뮬레이터에서 트랙패드/마우스 드래그, Android는 에뮬레이터 마우스 드래그, Web은 마우스와 가능하면 터치 에뮬레이션.
- 단계:
  1. 캔버스에 빠르게 긴 곡선, 느리게 짧은 획, 점 하나, 가장자리 근처 획, 화면 밖으로 나가는 획을 차례로 그린다.
  2. 되돌리기를 연속으로 눌러 획이 하나씩 사라지는지, 전체 지우기가 즉시 비우는지 본다.
  3. 미리보기에서 사인이 사진 위에 흰 획으로 어떻게 보이는지(배경 투명, 획 두께, 가장자리 매끄러움) 확인한다.
  4. 같은 획을 세 플랫폼에서 비슷하게 그려 미리보기를 나란히 비교한다.
- 기대 결과: 획이 끊기거나 뚝뚝 꺾이지 않고 입력과 렌더링의 지연이 거슬리지 않는다. 화면 밖으로 나간 획은 캔버스 안으로 보정된다. 점 하나도 원으로 보인다. 플랫폼 간 획 두께·여백 인상이 크게 다르지 않다(PNG 규격은 U에서 수치로 확인됨).
- 확인 방법: 단계별 스크린샷 비교(플랫폼 간 비교는 인상 기록, 픽셀 일치는 요구하지 않음), 이상 프레임 메모.
- 되돌릴 수 없음: 아니오(서버 호출 없음).
- 플랫폼 차이: 입력 장치(마우스, 트랙패드, 터치 에뮬레이션)에 따른 압력·속도 차이는 기록만 한다. Flutter·RN은 제스처 라이브러리 지연을 특히 본다.

### AG-SIGN-002 실서버 사인 변경 왕복과 반영

- 대응 TC: TC-SIGN-045
- 사전 조건: **실행 시 사용자에게 받은 카카오 계정**으로 로그인된 회원. 개발 서버 정상, 실제 S3 업로드와 사인 처리가 동작. 현재 사인을 미리 스크린샷으로 남겨 둔다(원복용 비교).
- 단계:
  1. 설정 탭의 사인 카드를 캡처한다.
  2. "사인 변경"으로 들어가 이전과 눈에 띄게 다른 모양(예: 큰 별 모양)을 그리고 미리보기에서 "사인 변경하기"를 누른다.
  3. 설정으로 돌아오면 토스트 "사인 반영까지 시간이 좀 걸릴 수 있어요!"가 뜨는지 확인한다.
  4. 5초 간격으로 설정 탭을 벗어났다 돌아와 사인 카드가 새 썸네일로 바뀔 때까지(최대 약 7분) 반복 확인한다. 바뀐 시점의 경과 시간을 기록한다.
  5. 다른 화면의 내 게시물(있다면 전시/피드)에서 사인 표시도 새 사인으로 바뀌었는지 확인한다.
  6. 변경 직후 한 번 더 같은 절차로 사인을 바꿔 연속 변경이 문제 없는지 확인한다.
  7. 원래 사인과 비슷하게 다시 그려 변경해 두고 종료한다.
- 기대 결과: 요청 성공 후 토스트. 처리 완료 전에는 기존 사인이 계속 보이고, 완료 후 GET /users/me/signature의 썸네일로 카드가 바뀐다(응답 originalImageUrl을 썸네일 자리에 대입하지 않는다). 처리 실패/시간 초과가 나면 SIGNATURE_REGISTRATION_REQUIRED로 "사인 재설정" 상태가 되고 다시 변경하면 복구된다. 5개 플랫폼에서 같은 결과.
- 확인 방법: 단계별 스크린샷, 디버그 로그에서 POST /users/me/signature/uploads → 사인 PUT → PUT /users/me/signature(요청 바디 필드 이름) → GET /users/me/signature 시퀀스와 응답 상태, 사용자에게 받은 토큰으로 `GET /users/me/signature`를 읽기 전용 조회해 URL 변화 확인(URL 값만 이전/이후 비교, 토큰 비기록).
- 되돌릴 수 없음: 예(회원의 활성 사인이 교체된다. 이전 사인 이미지는 복원 수단이 없다). 실행 전 사용자에게 알린다.
- 플랫폼 차이: iOS 시뮬레이터, Android 에뮬레이터, 웹 브라우저. 처리 시간은 서버 상태라 플랫폼 차이가 아니며 한 플랫폼에서 느리면 다른 플랫폼 결과와 시간을 분리해 기록한다. 같은 계정으로 여러 플랫폼을 연속 수행하면 마지막 사인이 남는다.
