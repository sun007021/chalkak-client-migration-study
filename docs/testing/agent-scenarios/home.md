# 에이전트 시나리오: 홈·배너(HOME, BANR)

자동화가 어려운 홈·배너 확인을 서브에이전트가 시뮬레이터와 개발 서버에서 직접 수행한다. 대응 TC는 [catalog/home.md](../catalog/home.md)이다.
공통 규칙(모든 시나리오): 서버는 개발 서버 `https://chalkak-dev.pysun.kr/api/v1/`이다. 테스트 계정은 **실행 시 사용자에게 받은 카카오 계정**을 쓰며 문서·로그·스크린샷 파일명·커밋에 계정 정보와 토큰을 적지 않는다. 서버 API 조회가 필요하면 앱 디버그 로그나 사용자가 알려 준 값을 환경변수(`CHALKAK_ACCESS_TOKEN` 등)로만 다루고 출력에 남기지 않는다. 클라우드 컨테이너의 `curl`은 프록시 때문에 개발 서버에 닿지 않으므로(strategy §6) 사용자 Mac의 시뮬레이터·에뮬레이터와 Mac 터미널에서 실행한다. 스크린샷은 `agent-runs/<날짜>/<플랫폼>/AG-<영역>-NNN-<단계>.png`처럼 저장하고 계정 정보가 보이면 가린다. 결과는 패리티 매트릭스의 `A✓`로 기록한다. 플랫폼은 iOS, Android, Flutter(iOS·Android), React Native(iOS·Android), Web 순서로 같은 시나리오를 수행하고, 아래 "플랫폼 차이"에 적은 곳만 단계가 다르다.

### AG-HOME-001 개발 서버 실데이터로 홈 레이아웃 확인

- **대응 TC**: TC-HOME-059
- **사전 조건**:
  - 앱을 `API_BASE_URL`=개발 서버 빌드로 설치(시뮬레이터/에뮬레이터/브라우저). 카카오 로그인은 실행 시 받은 계정으로 진행한다.
  - 개발 서버에 오늘 OPEN 주제, 어제 주제와 랭킹 후보 게시물(APPROVED), 배너 1개 이상이 있어야 한다. 없으면 사용자에게 알리고 있는 만큼만 확인한다.
  - 가능하면 오늘 게시물이 없는 계정 상태(히어로 Empty)에서 시작한다.
- **단계**:
  1. 앱 실행 → 스플래시 → 홈 최상단을 스크린샷으로 남긴다.
  2. 아래로 천천히 스크롤하며 "이번 주 기록", "어제 랭킹", "오늘 인기있는 사진", "ISSUE" 섹션을 각각 스크린샷으로 남긴다.
  3. 당겨서 새로고침을 한 번 하고 섹션이 깜빡이거나 비는 구간이 있는지 본다.
  4. 시스템 글꼴 크기를 가장 크게 바꾸고(지원 플랫폼) 같은 화면을 다시 확인한다. 다크 모드가 있으면 전환해서 확인한다.
  5. 로그아웃 후 "로그인 없이 사진 둘러보기"로 들어가 게스트 홈(히어로 Empty, 주간 기록 빈 상태)을 확인한다.
- **기대 결과**(관찰 가능한 것):
  - 섹션 제목·문구가 잘리거나 겹치지 않고 이미지 비율이 일그러지지 않는다.
  - 히어로가 서버 상태와 같은 모양이다(미작성이면 "{주제}" 사진을 공유하지 않았어요 + 업로드 진입).
  - 랭킹은 최대 5장, 배너 영역이 비어 있으면 ISSUE 섹션이 숨겨진다.
  - 게스트 홈에서 로그인이 필요한 영역(주간 기록, 히어로 CTA)이 오류 없이 안내 상태다.
- **확인 방법**:
  - 스크린샷 세트(최상단, 각 섹션, 큰 글꼴, 게스트).
  - 공개 API로 대조: `GET /topics?date=<오늘>`, `GET /posts?topicDate=<오늘>&sort=popular&page=1&pageSize=20`, `GET /banners?page=1&pageSize=10`의 항목 수·순서가 화면과 같은지 본다.
  - 회원 데이터는 사용자가 알려 준 값으로 `GET /posts/today`를 조회해 히어로 상태와 비교한다.
- **되돌릴 수 없음 여부**: 해당 없음(조회만 한다).
- **플랫폼 차이**:
  - Web: 브라우저 폭을 모바일 폭(390px)과 데스크톱 폭(1280px) 두 가지로 확인한다.
  - iOS: Liquid Glass 지원 OS와 평면 디자인(구형 OS) 둘 다 있으면 모두 확인한다.

### AG-HOME-002 실제 KST 자정 통과 시 홈 갱신

- **대응 TC**: TC-HOME-060
- **사전 조건**:
  - 개발 서버에 내일(KST) 주제가 00:00 KST에 시작하도록 등록돼 있는지 사용자에게 확인한다(관리자 작업은 앱 범위 밖). 없으면 "자정 이후 주제 없음(NoOpenTopic)" 경로를 확인하는 시나리오로 바꾼다.
  - 자정 5분 전부터 앱이 홈 화면에 떠 있고 기기 시간대가 어떤 값이어도 상관없다(UTC로도 한 번 반복하면 좋다).
  - 시간이 오래 걸리는 시나리오다. 플랫폼 마무리 단계에서 한 번만 수행한다.
- **단계**:
  1. KST 23:55에 홈을 열고 라벨("10월 27일 · 오늘의 주제")·어제 랭킹 날짜·히어로를 스크린샷으로 남기고 `GET /topics?date=<오늘>`을 조회해 둔다.
  2. KST 00:00:30까지 앱을 홈에 둔 채 기다린다(화면은 켜 둔다).
  3. 홈이 스스로 갱신되는지 본다. 갱신되지 않으면 앱을 백그라운드로 보냈다가 포그라운드로 복귀시킨다.
  4. 갱신 후 라벨, 어제 랭킹, 히어로, 주간 기록 범위를 다시 스크린샷으로 남긴다.
  5. (선택) 일요일 00:00을 지나는 날이면 이번 주 범위가 바뀌는지도 확인한다.
- **기대 결과**(관찰 가능한 것):
  - 자정 이후 라벨이 새 날짜(10월 28일)로 바뀌고 이전 날짜 콘텐츠가 섞이지 않는다.
  - 어제 랭킹이 10/27 기준이 되고 히어로가 새 주제 상태(또는 NoOpenTopic)로 바뀐다.
  - 갱신 중 오류 토스트가 뜨지 않는다.
- **확인 방법**:
  - 스크린샷 전후 비교와 앱 로그의 요청 날짜 쿼리(`topics?date=`).
  - 공개 API로 `GET /topics?date=2026-10-28`(자정 이후)이 200인지 확인한다.
  - 참고: 기기 시각만 앞당기면 서버는 아직 전날이라 `GET /topics?date=<내일>`이 400(미래 날짜)이 된다. 이는 이 시나리오의 합격 기준이 아니다.
- **되돌릴 수 없음 여부**: 해당 없음(조회만 한다).
- **플랫폼 차이**:
  - Android 에뮬레이터는 시스템 시각을 바꿔 클라이언트 계산만 확인할 수 있으나 서버 응답이 달라지지 않으므로 합격 판정은 실제 자정으로 한다.
  - iOS 시뮬레이터는 호스트 Mac 시각을 따른다.

### AG-BANR-001 실제 배너 웹뷰와 외부 브라우저 전환

- **대응 TC**: TC-BANR-030
- **사전 조건**:
  - 개발 서버 `GET /banners`에 배너가 1개 이상 있다(링크가 있는 웹페이지가 이상적).
  - 로그인 상태와 게스트 상태 모두 필요하다.
- **단계**:
  1. 홈의 ISSUE 섹션에서 배너를 탭한다(연타도 한 번 해 본다).
  2. 웹뷰에 페이지가 완전히 로드되는지 스크린샷으로 남긴다.
  3. 페이지 안의 외부 링크를 탭한다(같은 호스트 링크도 한 번).
  4. 시스템 브라우저가 열리는지 확인하고 앱으로 돌아온다.
  5. 페이지 안의 같은 문서 앵커 링크가 있으면 탭한다.
  6. 뒤로가기로 홈에 돌아와 스크롤 위치와 배너 목록이 유지되는지 본다.
  7. 게스트로 로그아웃하고 같은 배너를 다시 연다.
  8. 비행기 모드로 배너를 탭해 오류 화면과 "다시 시도"를 확인한 뒤 네트워크를 복구하고 다시 시도한다.
- **기대 결과**(관찰 가능한 것):
  - 웹 콘텐츠가 깨짐 없이 보이고 연타해도 웹뷰는 하나만 열린다.
  - 링크 탭은 시스템 브라우저(또는 Web은 새 탭)로 열리고 앱 안에서 이동하지 않는다. 앵커 이동은 웹뷰 안이다.
  - 게스트도 로그인 요구 없이 웹뷰가 열린다.
  - 오프라인에서 "페이지를 불러오지 못했어요"와 "다시 시도"가 보이고 복구 후 로드된다.
- **확인 방법**:
  - 스크린샷(웹뷰, 브라우저 전환, 오류 화면).
  - 앱 로그의 `screen_view` `issue` 1회.
  - 공개 API `GET /banners`의 `webViewUrl`과 웹뷰 주소 비교.
- **되돌릴 수 없음 여부**: 해당 없음.
- **플랫폼 차이**:
  - Web: 링크는 새 탭으로 열린다. iOS 시뮬레이터에서는 Safari가 열린다.
  - Android 에뮬레이터에 브라우저가 없으면 토스트 "링크를 열 수 있는 브라우저가 없어요"가 뜨는 것도 확인 대상이다.
