# 에이전트 시나리오: 기록(REC)

OS 권한 다이얼로그와 갤러리 저장, 실데이터 시각 확인이다. 대응 TC는 [catalog/record.md](../catalog/record.md)이다.
공통 규칙(모든 시나리오): 서버는 개발 서버 `https://chalkak-dev.pysun.kr/api/v1/`이다. 테스트 계정은 **실행 시 사용자에게 받은 카카오 계정**을 쓰며 문서·로그·스크린샷 파일명·커밋에 계정 정보와 토큰을 적지 않는다. 서버 API 조회가 필요하면 앱 디버그 로그나 사용자가 알려 준 값을 환경변수(`CHALKAK_ACCESS_TOKEN` 등)로만 다루고 출력에 남기지 않는다. 클라우드 컨테이너의 `curl`은 프록시 때문에 개발 서버에 닿지 않으므로(strategy §6) 사용자 Mac의 시뮬레이터·에뮬레이터와 Mac 터미널에서 실행한다. 스크린샷은 `agent-runs/<날짜>/<플랫폼>/AG-<영역>-NNN-<단계>.png`처럼 저장하고 계정 정보가 보이면 가린다. 결과는 패리티 매트릭스의 `A✓`로 기록한다. 플랫폼은 iOS, Android, Flutter(iOS·Android), React Native(iOS·Android), Web 순서로 같은 시나리오를 수행하고, 아래 "플랫폼 차이"에 적은 곳만 단계가 다르다.

### AG-REC-001 달력 이미지 저장과 OS 권한

- **대응 TC**: TC-REC-044
- **사전 조건**:
  - 기록이 있는 달(사진 2장 이상)이 있는 계정으로 로그인한다.
  - 권한 상태를 초기화한다: iOS `xcrun simctl privacy booted reset photos`, Android 앱 데이터 삭제 또는 `adb shell pm reset-permissions`.
- **단계**:
  1. 기록 탭에서 기록이 있는 달을 연다.
  2. "이미지로 저장"을 누른다. OS 권한 다이얼로그가 뜨면 먼저 "허용 안 함"을 선택하고 토스트 "이미지 저장 권한이 필요해요"를 확인한다(권한 다이얼로그가 뜨지 않는 OS 버전이면 이 단계는 생략한다).
  3. 시스템 설정에서 권한을 허용한 뒤 다시 "이미지로 저장"을 눌러 토스트 "달력을 이미지로 저장했어요"를 확인한다.
  4. 기기 앨범에서 저장된 PNG를 열어 월 제목, 요일 헤더, 날짜 칸, 썸네일이 보이는지 확인한다(Android 파일명 `chalkak-calendar-<yyyy-MM>.png`).
  5. 저장 버튼을 빠르게 두 번 눌러 이미지가 한 장만 저장되는지 확인한다.
- **기대 결과**(관찰 가능한 것):
  - 권한 거부 시 앱이 멈추지 않고 안내 토스트만 뜬다.
  - 저장된 이미지가 화면의 달력과 같은 내용이며 잘림·검은 영역이 없다.
  - 연타해도 한 장만 저장된다.
- **확인 방법**:
  - 스크린샷(권한 다이얼로그, 토스트), 앨범에서 연 PNG 캡처.
  - Android는 `adb shell ls /sdcard/Pictures/Chalkak/`로 파일명·개수 확인.
- **되돌릴 수 없음 여부**: 저장된 이미지 파일은 기기 앨범에 남는다(서버 영향 없음). 직접 삭제한다.
- **플랫폼 차이**:
  - Web: 파일 다운로드로 저장되며 OS 권한 다이얼로그가 없다(브라우저 다운로드 바 확인).
  - Android API 28 이하는 저장소 쓰기 권한 다이얼로그가 뜬다.
  - iOS는 사진 추가 전용 권한이다.

### AG-REC-002 개발 서버 실데이터로 기록 화면 확인

- **대응 TC**: TC-REC-045
- **사전 조건**:
  - 기록 데이터가 여러 달에 걸쳐 있는 계정이 좋다. 오늘 PENDING 게시물이 있으면 "사진 반영 중" 배지 확인이 가능하다.
  - 로그인 상태.
- **단계**:
  1. 기록 탭을 열어 현재 달 달력과 월 선택 시트를 스크린샷으로 남긴다.
  2. 이전·다음 달로 이동하고 기록 없는 달로도 이동해 본다.
  3. 날짜를 선택해 사진 패널을 본다. APPROVED면 "피드에서 보기"와 "전시 보러가기"를, PENDING이면 "사진 반영 중" 배지와 안내 문구를 확인한다.
  4. "전시 보러가기"로 이동한 뒤 뒤로 가서 기록으로 돌아오는지 본다.
  5. 홈의 이번 주 기록 칸을 탭해 기록 탭이 해당 날짜로 열리는지 본다.
- **기대 결과**(관찰 가능한 것):
  - 달력 배치(일요일 시작, 요일 헤더)와 썸네일 비율이 자연스럽고 월을 넘나들어도 레이아웃이 깨지지 않는다.
  - PENDING 배지와 안내가 보이고 액션 버튼은 숨겨진다.
- **확인 방법**:
  - 스크린샷 세트.
  - 사용자가 알려 준 토큰으로 `GET /posts/calendar/months`, `GET /posts/calendar?year=<연>&month=<월>`을 조회해 화면의 날짜·상태와 대조한다(토큰 비출력).
- **되돌릴 수 없음 여부**: 해당 없음(조회만 한다).
- **플랫폼 차이**:
  - Web: 창 폭에 따른 달력 레이아웃을 모바일·데스크톱 두 폭으로 확인한다.
